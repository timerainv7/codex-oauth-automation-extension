# CPAM ReAuth: 安全替换、重试与停用账号删除

## 目标

在既有 CPAM ReAuth 结果页中增加可控的 CPA 认证文件安全替换、非停用失败项重试，以及已停用账号的批量删除能力。安全替换默认开启。

## 设置

新增持久化布尔设置 `cpamReauthReplaceOriginalFile`，默认 `true`：

- 开启：每条 OAuth 成功后执行安全替换，最终保留 CPAM 巡检中原 401 文件名。
- 关闭：保留 CPA OAuth 流程自动生成的文件名，不执行文件轮询、覆盖或清理。

侧边栏在 CPAM ReAuth 卡片中提供此开关及简短说明，运行中锁定设置。

## 安全替换数据流

1. ReAuth 候选保留原 `fileName`、邮箱、账户 ID 和认证索引。
2. OAuth 回调验证完成后，若开关开启，控制器轮询 CPA auth-file 列表，等待本轮账号的新认证文件出现。
3. 通过候选的邮箱或账户 ID、并排除原文件名，确定新生成文件；下载其内容。
4. 调用 CPA `POST /v0/management/auth-files?name=<原 fileName>`，以新文件内容覆盖原文件名。
5. 覆盖成功后，调用 CPA `DELETE /v0/management/auth-files?name=<新 fileName>` 清理重复的新文件。
6. 在覆盖成功前绝不删除原文件。轮询、下载、覆盖或清理失败时，将该账户标为 `failed`、步骤为 CPA 文件替换；旧文件仍保留。

CPA 凭据内容、管理密钥、回调 URL 均不得写入运行状态、结果或日志。

## 结果操作

终态结果区增加两个操作：

- **重试 ReAuth（N）**：只选择本次运行中 `failed` 且不是 `account_deactivated` 的项目；候选顺序与原运行一致，不再请求 CPAM。重试结果替换相应项目的最新状态、步骤和错误，并重算汇总。
- **删除已停用账户（N）**：只选择本次运行中明确为 `account_deactivated` 的失败项目。用户二次确认后按顺序逐个调用 CPA 删除原 `fileName`；每项保存删除成功或失败的状态与原因，已成功删除的项目不重复删除。

两个操作均在 ReAuth 运行结束后可用，执行期间禁用开始、停止和其他结果操作。网络或单个 CPA 操作失败不会中断后续项目。

## API 边界

扩展的 CPA API 模块新增 auth-file 的列表、读取、覆盖与删除封装；所有调用沿用 CPA 管理地址和管理密钥的现有认证头。控制器只通过这些封装执行文件替换与删除，不直接构造 HTTP 请求。

## 测试

- CPA API：列表、读取、覆盖、删除请求的路径、认证头、超时与错误处理。
- 控制器：安全替换开关关闭时不调用文件 API；开启时严格遵循“发现新文件 → 覆盖旧文件 → 删除新文件”；任一失败不删除旧文件。
- 重试：只重试非停用失败项、保持原顺序、不重新拉取 CPAM，并更新项目和汇总。
- 删除：仅删除停用项、需要确认、逐项继续、保存每项删除结果、不会重复删除。
- 侧边栏：开关默认开启且持久化，终态按钮计数、确认交互、忙碌锁定和结果显示均正确；敏感信息不渲染。
